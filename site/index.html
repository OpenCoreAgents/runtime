Run agents on-device or on your own workers.

OpenCore Agents is a TypeScript runtime that can run inside a browser or across an API and background workers. Give a planner the ability to define and queue subagents as work comes in.

Run the example Read the engine reference

Run lifecycle

  1. RunLoad an agent into a session and send input.
  2. ActExecute a tool and pass its result back to the model.
  3. Wait and resumePause for input and continue with the same run ID.
  4. CompleteReturn a result and retain the run history.

Why OpenCore Agents

Run the agent inside the browser

Keep run history, memory, and agent definitions in IndexedDB. On WebGPU-capable devices, the browser example can run model inference in a Web Worker using WebLLM.

Explore the browser example

Create and queue subagents at runtime

A planner can give a new subagent instructions, tools, and a model, persist its definition, and enqueue its run. It can then wait for the result and use it in the parent run.

Explore the planner tools

Load agent configuration when a job runs

Workers can load agent, skill, and HTTP tool definitions from Redis when they pick up a job. Update prompts and tool configuration without redeploying those workers.

Read the dynamic definitions guide

Wire the runtime into infrastructure you own

Start with the Express, Redis, and BullMQ reference stack. Inject your own model, memory, run store, and messaging adapters as your deployment needs change.

Read the adapter contracts

Run your first agent

The minimal example uses a deterministic mock model and in-memory state. It requires Node.js and pnpm, with no model API key.

Read the minimal example 
git clone https://github.com/OpenCoreAgents/runtime.git
cd runtime
pnpm install
pnpm turbo run build --filter=@opencoreagents/core
pnpm --filter @opencoreagents/example-minimal-run start
