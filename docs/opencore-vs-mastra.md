# OpenCore Agents and Mastra

OpenCore Agents gives application teams control over where their agent runtime runs and how it dispatches work. Its strongest differentiators in this review are on-device inference in a browser and a planner that can create a subagent definition and dispatch it as a background job. Mastra offers more integrated tooling for typed workflows, agent versioning, observability, and evaluation.

This comparison uses the OpenCore source at `817f76a` on `ft/canonical-tool-input` and Mastra's official documentation as reviewed on November 20, 2026. OpenCore findings are based on implementation, exports, examples, and test cases. This review did not run either stack or benchmark performance, cost, or crash recovery.

## Policy pipeline integration

The consolidated branch adds a tool visibility policy and a pre-execution policy that evaluates canonical arguments and can allow, deny, or suspend a call for approval. The SDK can approve, reject, or cancel a pending action, and it evaluates the policy again at approval time. It also exposes versioned public events with a configurable redactor and event sinks. [Visibility policy](../packages/core/src/engine/toolVisibilityPolicy.ts) · [Execution policy](../packages/core/src/engine/executionPolicy.ts) · [Approval API](../packages/core/src/engine/approvalApi.ts) · [Public events](../packages/core/src/engine/publicEvents.ts)

Approval currently requires an approval-capable run store. The bundled in-memory store implements the pending-action claim, and the reference Redis/BullMQ app still needs a persistent implementation and HTTP wiring. Its SSE interface continues to use the separate Redis lifecycle hooks. [Run store contract](../packages/core/src/adapters/run/RunStore.ts) · [In-memory store](../packages/core/src/adapters/run/InMemoryRunStore.ts) · [Runtime server](../apps/runtime/src/server.ts)

## Implications

OpenCore is a strong fit when the product needs on-device inference, subagents assembled at runtime, or direct ownership of a Redis and BullMQ execution stack. Its project and tenant identifiers give a host application inputs for scoping runs. The host still owns identity mapping and authorization, and it must account for retries and idempotency when tools have external effects. [Production considerations](roadmap/technical-debt-security-production.md)

Mastra is a strong fit when the team needs typed workflows, agent revision management, and an integrated workflow for inspecting and evaluating agents. For an existing OpenCore deployment, the most informative migration test would use a representative project with dynamic subagent creation, a long-running tool with side effects, and a pause followed by a process restart. Check run identity, definition revision, tenant boundaries, and tool behavior under retry in both systems.
